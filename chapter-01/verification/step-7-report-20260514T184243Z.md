## 5. PDF export decision

Per spec 7.3 fallback authorization, the export endpoint ships **JSON**:

```json
{
  "schema_version": "1.0",
  "exported_at": "<ISO>",
  "user_id": "<uuid>",
  "brand_name": "<from qbp>",
  "foundation_locked_at": "<ISO or null>",
  "qbp": { ... full QBP document ... }
}
```

Reasoning:
- Edge runtime restricts PDF libraries. `@react-pdf/renderer` is React-bound and requires a build step.
- `pdf-lib` is pure ESM and would work, but introduces a runtime dep with no lock file — repo discipline is "minimal deps".
- The fallback authorization in spec 7.3 was the right escape valve.

JSON is honest: every QBP field round-trips, the file is downloadable, and a Chapter 1 polish pass can render PDF from this JSON server-side once the design surfaces in steps 9–10 lock the visual treatment. `format: 'json'` and a `format_note` field are returned with the signed URL so the frontend can label the download accurately.

## 6. Iteration trail

End-to-end smoke testing on PR #35 surfaced two failures that landed in PR #36:

### 6.1 Vercel legacy `routes:` config does not auto-resolve `[id].js`

The vercel.json uses the legacy `routes:` schema (rewrites: was never adopted), and `handle:filesystem` under that schema does not expand `[param]` filename brackets. `/api/artifacts/<uuid>` matched the catch-all 404. Fix: explicit UUID-pattern rewrites added before `handle:filesystem`:

```json
{ "src": "/api/artifacts/([0-9a-fA-F-]{36})/regenerate", "dest": "/api/artifacts/[id]/regenerate" },
{ "src": "/api/artifacts/([0-9a-fA-F-]{36})",            "dest": "/api/artifacts/[id]" }
```

The 36-char UUID pattern is strict, so the rewrite cannot shadow the `/api/artifacts` list endpoint or any future static asset.

### 6.2 Supabase Storage GET returns HTTP 400 (not 404) when bucket missing

`ensureBucket` was gated on `r.status === 404`. The Storage REST actually returns HTTP 400 with `body.statusCode === '404'` for a missing bucket. The bucket creation path was never reached, and 1 of 11 starter-tier tests failed with `Storage bucket unavailable`. Fix: any non-200 GET triggers a POST create, followed by a verify GET on POST failure (race-safe).

Bucket `qbp-exports` was created during the diagnostic call and persists in production.

## 7. Surprises and notes

### 7.1 JWT minting via admin generate_link

`SUPABASE_JWT_SECRET` is not in the Vercel env (Supabase verifies tokens via its own `/auth/v1/user` endpoint, so the secret never needs to leave Supabase). The test script mints a real session by calling `auth/v1/admin/generate_link` with `type=magiclink`, reading the `hashed_token` from the response (top-level field, not nested under `properties`), and exchanging it via `auth/v1/verify`. No email is triggered — admin generate returns the token in-band.

### 7.2 Webhook extension applies cleanly to existing flow

The extended `api/stripe-webhook.js` keeps the email-match fallback for legacy checkout sessions created before this PR. New checkouts (via `/api/stripe/checkout`) include `client_reference_id` and `metadata.tier_intent`, so the webhook can map back to the user without an email round-trip. Idempotency via `stripe_events` is best-effort: the dedup logic checks whether the existing row is older than 5 seconds, which handles redeliveries while allowing the first-time-through path to proceed. A second redelivery within 5 s would over-process — not a real risk given Stripe's retry cadence (default ~1 min apart).

### 7.3 Webhook URL stays at `/api/stripe-webhook` (flat)

The spec referenced `/api/stripe/webhook.js` but the existing webhook is registered with Stripe at the flat `/api/stripe-webhook` path. Moving would require Stripe Dashboard reconfiguration. I extended the existing flat file rather than build a parallel subdirectory version. `/api/stripe/checkout.js` is a brand new endpoint so it goes in the subdirectory as the spec asks.

### 7.4 Regenerate of Soul Map kicked a real run

The `POST /api/artifacts/<soul_id>/regenerate` assertion produced a real run against Anthropic via the dispatch chain. The test accepts status 200 (kicked) OR 409 (in-flight). Both indicate the endpoint is wired correctly; the test does not poll to completion. Run shows up in `artifact_runs` for audit.

### 7.5 Tier flip is atomic and reverts cleanly

The test script flips `profiles.tier` via PostgREST PATCH for the duration of the starter-tier block and restores to `'free'` at the end. Post-test SQL query confirmed: `tier='free'`. No residual state in production.

### 7.6 PDF deferral is recorded for Chapter 1 polish pass

`api/qbp/export.js` returns `format: 'json'` and a `format_note` field on every successful export. The frontend in step 13 (Paywall surface) will surface this honestly: "Download your QBP as JSON" until the PDF pipeline lands.
