## 2. Soul Map Synthesizer — what changed

### 2.1 Prompt

The model now returns ONLY the textual body:

```json
{
  "essence":             "prose",
  "paradox":             "prose",
  "manifesto":           "prose",
  "archetype":           "prose",
  "what_we_are_reading": "prose",
  "what_we_refuse":      "prose",
  "always": ["...", "...", "..."],
  "never":  ["...", "...", "..."]
}
```

No `schema_version`, `header`, `footer`, or `generated_at` is emitted by the model. The agent function `assembleArtifact()` wraps the body server-side with the canonical envelope:

```
header.eyebrow      = "01 Discovery · Soul Axis"
header.title        = `The Soul of ${qbp.brandName || "Your Brand"}`
header.agent        = "soul_map_synthesizer"
header.generated_at = new Date().toISOString()
header.version      = 1
body_sections       = 6 prose sections
data_blocks         = [{ type: "always_never", title: "Binding commitments", content: { always, never } }]
footer.qbp_fields_referenced = SOUL_MAP_FIELDS filtered to those actually present
```

Server-control eliminates a class of validation failures (wrong generated_at, missing agent slug, mismatched schema_version) before they can leave the agent.

### 2.2 Drops

- `_meta.missing_inputs` no longer lives in the artifact body. The agent returns the `missing` list separately to the dispatcher, which logs it on `artifact_runs.error` for the run record. Reading surface in step 9 never has to special-case `_meta`.
- The flat fields `archetype.primary` / `archetype.interpretation` / `observed_pattern` are gone. They map to the new body_section headings `Archetype` and `What we are reading`.

### 2.3 Timeout

`AbortController` aborts the Anthropic call at 22 s. On abort the agent returns `{ ok: false, error: 'edge_timeout' }`. The dispatcher maps that to `artifacts.status='failed'` and an `artifact_runs.error` payload of `{stage: 'claude-call', error: 'edge_timeout'}`.

### 2.4 Token logging

`callClaude()` reads `usage.input_tokens` and `usage.output_tokens` from the API response and surfaces them through `result.meta`. Dispatcher writes them to `artifact_runs.tokens_in` / `tokens_out` on close.

## 3. Dispatch — what changed

### 3.1 Validator import

```js
import { validateArtifact } from '../../js/qb-artifact-schema.js';
```

Cross-directory import works on Vercel Edge — the bundler treats the validator as a regular ESM dep. No copy or duplicate maintained.

### 3.2 Status flow

```
queued        ← artifact_runs.findOrCreateArtifact (insert)
   ↓
generating    ← patchArtifact before agent call
   ↓
delivered     ← patchArtifact after successful validation
   ↓
   (or)
failed        ← patchArtifact on agent error or schema validation failure
```

Legacy `producing` and `ready` are gone. Migration 008's strict CHECK rejects any future write of the old vocabulary.

### 3.3 Idempotency and versioning

The old `(user_id, artifact_type)` unique constraint was dropped in migration 002. The new flow:

1. Look up rows for the same `(user_id, artifact_type)` where status IN ('queued', 'generating').
2. If one exists: reuse it. Return `{ status: 'in_flight' }`. No agent call, no duplicate run.
3. Otherwise: look up the highest existing version for the same `(user_id, artifact_type)`. Insert a new row with `version = max + 1`, `parent_artifact_id = previous.id`, `status = 'queued'`.

This satisfies CHAPTER_01_SPEC §5.1 ("if an artifact is already queued or generating for this user + agent_slug + version, return existing artifact_id without enqueuing again") and §4.3 ("`parent_artifact_id` References previous version when regenerated").

### 3.4 artifact_runs writes

Every dispatch:

1. Opens a row at the start: `status='started'`, `agent_slug`, `model`.
2. Closes the row at the end with one of:
   - `succeeded` + `duration_ms` + `tokens_in` + `tokens_out` + optional `error: JSON({ missing_inputs })`
   - `failed` + `duration_ms` + `error: JSON({ stage, error, detail })` (truncated to 1000 chars)

Service role writes only (per spec 4.6). Users SELECT via the RLS policy that joins on `artifacts.user_id`.

### 3.5 Validate-before-save

```js
const validation = validateArtifact(result.content);
if (!validation.valid) {
  // status='failed', error='schema_validation_failed', content stays {}
  // artifact_runs.error logs the full errors array
  return failure;
}
// status='delivered', content=validation.content
```

Invalid content never lands in `artifacts.content`. If a future agent regression produces drift, the row records the failure and the reading surface shows the failed state per spec 9.6.

### 3.6 Phase

Set via `AGENT_REGISTRY[slug].phase`. Soul Map = `'01'`. All future agents declare their own.

### 3.7 Backward-compatible inbound name

The old kebab `soul-map-synthesizer` agentName is accepted at the request boundary via `AGENT_NAME_ALIASES` and normalized to the canonical underscore form. Caller migration can happen incrementally without breaking in-flight requests.

## 4. Migration 008

Applied to production:

```sql
alter table public.artifacts alter column status set default 'queued';

alter table public.artifacts add constraint artifacts_status_check
  check (status in ('queued', 'generating', 'delivered', 'failed'));
```

Pre-apply check: `select status, count(*) from public.artifacts group by status` → one row, `delivered`. Safe to apply, no constraint violation possible.

Post-apply: constraint active. Any attempt to write a row with `status` outside the four values now fails at the database.
