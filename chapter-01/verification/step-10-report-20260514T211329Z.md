### 2.1 Notes per section

- **Soul Axis** sub-blocks: Essence / Paradox / Manifesto / Anti-brand / Archetype / Binding commitments. Each renders its own sub-empty (italic) when its source field is missing inside an otherwise-populated section.
- **Sensescape** groups its sub-blocks into three sense cards: Sight (color + typography), Sound (signature + anti-voice), Touch (object + moment + gesture). ## 10. Surprises and notes

### 10.1 Test user foundation is already locked

`foundation_locked_at = 2026-05-14T08:28:13` for the test user. This was set during the step-3 / step-6 lifecycle. The cover therefore shows **Locked** rather than **Draft** even though the user only has archetype data. The locked status is about Phase 01 completion, not content density — the cover badge surfaces both honestly.

### 10.2 Visual DNA + War Table sections lock on **read tier**, not on content presence

A free user with completed Visual DNA / War Table exercises still sees the locked frost on those sections. This matches `canReadArtifact` semantics from step 7 (Soul Map is always-free; others require Starter+). A user-provided record on a paid section is still gated for read. If we wanted to differentiate "user has content but cannot read it" from "user has no content", we would need a separate query — out of scope for step 10.

### 10.3 Sensescape smell + taste are agent-derived, not user-provided

The Sensescape exercise does not capture smell or taste as discrete fields. The Sensescape Synthesizer derives them at run time from adjacent QBP signals (object, color territory). The QBP page reflects what the user provided; smell and taste live only in the Sensescape **artifact** at `/artifact/<id>`. Sub-block omission rule keeps the page honest.

### 10.4 Export is JSON, surface label says so

Honest JSON-download note in the toast: `Downloading as JSON (PDF format coming soon).` Matches the step-7 deferral. A future polish PR can flip the format silently once PDF generation lands; the toast text can update at that point.

### 10.5 Tier read from session bag

The page reads `tier` from the qb-cloud session object (`QB.getSession().tier`), not from `/api/qbp`. This matches existing dashboard logic and keeps API responses focused on QBP content. `/api/qbp` returns `qbp` + `foundation_locked_at` + `last_updated`; the tier is read from the auth session the same way dashboard.html reads it.

### 10.6 Reading-width discipline

Sub-block bodies cap at `max-width: 65ch` for readability. `.qb-qbp-subblock.is-wide` opt-out used for the always/never columns and other side-by-side layouts that want full container width.

### 10.7 Auth callback note

Unauthenticated users land on `/signal-scan.html?reason=signin&return_to=%2Fqbp`. After magic-link sign-in, the auth-callback returns them to `/qbp`. Confirmed by reading the qb-cloud session bag wiring — same flow as `/artifact`.
