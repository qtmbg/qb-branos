## 3. Routing rule for `_archive/`

Added to `vercel.json` immediately after the bare-host root rules:

```json
{
  "src": "/_archive(/.*)?",
  "status": 404,
  "dest": "/404.html"
}
```

This rule is positioned BEFORE the redirect rules for `/dashboard`, `/hub`, `/qb-branidos-hub.html`, and `/journey-guide`, so the path-based redirects continue to fire even though the source files have moved. The `_archive/` deny rule catches direct attempts to bypass the redirect chain by hitting the archived file directly.

## 8. Surprises and notes

### 8.1 The deprecation banner content was rewritten three times

The banner shipped in step 12 already said the right thing (deprecated, redirected to /foundation). The step 16 rewrite tightens it to a single canonical block with consistent wording: "DEPRECATED. Chapter 1 retirement, 2026-05-15. Replaced by /foundation, /archive, /qbp. Kept for reference only. Do not link to. Do not edit." This is the version that will sit in the archive permanently.

### 8.2 vercel.json route ordering matters here

The `_archive/` 404 rule had to be placed BEFORE the deprecation redirect rules in `routes[]`. Vercel evaluates routes top-to-bottom. If `/dashboard(\\.html)?` → 301 ran first, then the archived `/_archive/chapter-1-deprecations/dashboard.html` request would still 404 because that specific path doesn't match the redirect pattern. But putting the deny on `/_archive/*` first guarantees the archive directory is never served, regardless of the redirect chain. Confirmed by curl: all three archived files return 404, all three redirect paths return their expected 301/410.

### 8.3 `brand-performance-dashboard.html` is not a deprecation

The audit grep returned hits in `tools.html`, `ecosystem.html`, `qb-cloud.js`, and `war-table.html` for the substring "dashboard". All of them refer to the Phase 05 tool `brand-performance-dashboard.html`, which is an agent-tool surface that ships in a later chapter. Its slug ("dashboard") is internal-only and does not collide with the retired `/dashboard` route. Confirmed by reading each match in context. Left alone.

### 8.4 Master Instruction + design system docs intentionally untouched

`QB_THINKING_MACHINE.md` and `docs/brand/qb-design-system-v3.4.md` both contain "qb-branidos-hub.html" and "journey-guide.html" references in their tool inventories. Per the step 16 prompt, those reconcile after Chapter 1 ships. Tracking that gap as part of the post-Chapter-1 cleanup.

### 8.5 Python script briefly blanked the files

While rewriting the deprecation banners with a regex pattern in Python, the first attempt accidentally zeroed out all three archived HTMLs. `git mv` had staged them but not committed, so they were still recoverable from HEAD. Restored via `git show HEAD:<path> > <new-path>` and rewrote the banner with a safer two-step approach (read the source, splice the banner in front of the doctype + comment block, write back). Time to recover: under a minute. No data loss. Lesson: regex substitutions on whole files are dangerous; a small splice script is safer.

### 8.6 Scripts now point at the new app surfaces

`scripts/mobile-audit.mjs` and `scripts/wire-canonicals.mjs` had the deprecated entries replaced with the new app surfaces (`foundation`, `archive`, `qbp`, `paywall`, `account`). Next time mobile audit or canonical-tag wiring runs, those surfaces get covered automatically. Not part of step 16's definition of done, but a useful side effect.

### 8.7 `qb-cloud.js` TOOL_FILES carries a 'dashboard' entry that is NOT deprecated

The map at line 80 reads `'dashboard': 'brand-performance-dashboard.html'`. This is an internal slug for the Phase 05 Brand Performance Dashboard tool, not the retired `/dashboard` route.
