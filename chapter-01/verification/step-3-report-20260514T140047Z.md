## 2. Agent contract (new)

`runSoulMapSynthesizer({ qbp, anthropicKey })` returns:

```
{
  ok: true,
  content: <schema-conforming artifact>,
  missing: <string[] of QBP keys not present>,
  meta: {
    agent_slug: 'soul_map_synthesizer',
    phase: '01',
    model: 'claude-sonnet-4-6',
    tokens_in: <int|null>,
    tokens_out: <int|null>
  }
}
```

On failure:

```
{ ok: false, error: 'edge_timeout' | '<message>', stage: '<stage>', detail?: '<truncated>' }
```

The model is instructed to return a flat object of prose/lists. The envelope (`schema_version`, `header`, `footer`) is constructed server-side. `header.title` is `"The Soul of ${qbp.brandName?.trim() || 'Your Brand'}"`. `header.generated_at` is `new Date().toISOString()`. `header.version` is `1`. `_meta.missing_inputs` is no longer embedded in artifact content; the dispatcher logs the missing list on `artifact_runs` instead.

Timeout: a Claude call that exceeds 22 s is aborted and the agent returns `error: 'edge_timeout'`. Dispatch maps that to `status='failed'` with no content saved.

## 3. Dispatch contract (new)

`POST /api/agents/dispatch` flow:

1. JWT verified, matches body.userId.
2. `agentName` resolved via `AGENT_REGISTRY` (canonical slugs) + `AGENT_NAME_ALIASES` (legacy kebab → canonical underscore).
3. `findOrCreateArtifact` checks for an in-flight row (`status in (queued, generating)`). If found, returns the existing row and `200 { status: 'in_flight' }`. Otherwise inserts a new row with `version = max(version) + 1` and `parent_artifact_id = <previous row id or null>`, `status = 'queued'`, `phase = registry.phase`.
4. `openArtifactRun` inserts an `artifact_runs` row with `status = 'started'`. The artifact is patched to `status = 'generating'`.
5. Agent runs. Result captured.
6. **Validate-before-save:** `validateArtifact(result.content)` is the gate. Invalid content does not reach `artifacts.content`. On `valid: false`:
   - artifact patched to `status = 'failed'`, `error = 'schema_validation_failed'`, `content = {}`.
   - artifact_runs closed as `failed` with `error` containing the validator errors array (truncated to 1000 chars).
7. On `valid: true`: artifact patched to `status = 'delivered'`, `error = null`, `content = validation.content`. artifact_runs closed as `succeeded` with `duration_ms`, `tokens_in`, `tokens_out` populated.
8. Artifact-ready email fire-and-forget.

Status vocabulary throughout: `queued`, `generating`, `delivered`, `failed`. No more `producing` / `ready`.

## 10. Surprises and notes

### 10.1 Unique-constraint upsert was retired

The prior dispatch relied on `unique(user_id, artifact_type)` for the `producing` upsert (`Prefer: resolution=merge-duplicates`). Step 1 migration 002 dropped that constraint to enable versioning. The new dispatch replaces upsert with `find-or-insert-with-incremented-version`. This is the correct shape for the spec's regenerate flow (5.7) but means the legacy "one row per (user, agent)" assumption no longer holds. Anything downstream that assumed at most one row per `(user_id, artifact_type)` now needs `order=version.desc&limit=1` or a similar selector. The Brand Archive list (step 11) and the Foundation page (step 12) will need to apply that pattern when they ship.

### 10.2 Inbound legacy slug accepted

Dispatch still accepts the legacy kebab agent name (`soul-map-synthesizer`) via `AGENT_NAME_ALIASES` so any browser tab loaded before this deploy continues to work for one or two minutes after rollout. Internal callers (`api/lock-foundation.js`, `dashboard.html`) all send the canonical slug.

### 10.3 Dashboard kept transitional

`dashboard.html` was patched to look up the renamed `artifact_type`, handle the new status labels, and render the envelope shape. The HTML and CSS structure was not redesigned: step 12 (Foundation page) replaces this surface. The patch is a non-regression minimum, not a polish pass.
