### 3.3 Factory module

`js/qb-components.js` exports 12 named factories + a default `QBComponents` object grouping all of them. Module sanity verified locally: 12 of 12 named + 12 of 12 default exports present.

Every factory:
- Accepts a single options object.
- Returns a ready-to-append `HTMLElement`.
- Adds the correct state-modifier classes.
- Wires event listeners passed via `onClick`, `onCta`, `onAction`, `onPrimary`, `onSecondary`.
- Throws on invalid state combinations (e.g. `createPhaseCard` with no state, or with `phase` outside `00–05`).
- Sanitises any `href` via `safeHref` so external strings cannot inject `javascript:` URLs.

## 5. Surprises and notes

### 5.1 Component class names follow the LOCKED source, not the spec template

The step-8 prompt named the pill button `.qb-pill-button` + `.qb-pill-button__slab`. The canonical class in `ecosystem.html` is `.qb-button` + `.qb-button_content`, with the slab implemented as a `::before` pseudo-element. CLAUDE.md and qb-design-system-v3.3.md both lock this naming. The shared CSS preserves the canonical names. The spec template was a rough sketch of the API surface; the canonical patterns govern.

### 5.2 `.qb-nav` shipped as CSS only

The spec lists `.qb-nav` as a section 3 component. Its brand wordmark, link list, and mobile-menu behavior depend on per-page decisions (active link, tier badge slot, route awareness) that step 12 (Foundation page) owns. The CSS is in place so any page can hand-roll the markup; the factory function is intentionally deferred.

### 5.3 PDF export note in spec section 5 still applies

Nothing in step 8 changes the step-7 PDF deferral. The `.qb-share-controls` factory exposes a `canDownloadPdf` flag so consumers can render the download button as enabled or disabled per tier; the actual download endpoint still ships JSON.

### 5.4 Pair spacings preserved

The locked source has seven pair-spacing tokens (`--space-3xs-2xs` through `--space-2xl-3xl`) the step-8 spec template did not mention. These are load-bearing for `.qb-x`, `.qb-x-narrow`, and `.qb-x-slim` layout utilities. Preserved verbatim.

### 5.5 `.qb-illus-card` brought along

The step-8 spec did not list `.qb-illus-card`, but it is a locked canonical pattern used wherever the illustration inventory is rendered. Including it in `qb-components.css` so future pages do not have to re-derive it.

### 5.6 No deps added

The components library is pure vanilla ES modules + CSS. `package.json` only carries the pre-existing `@vercel/og` dep. No build step, no transpilation, no framework. Matches repo discipline.

### 5.7 Reduced-motion: dual trigger

Both `@media (prefers-reduced-motion: reduce)` and the manual `.qb-reduced-motion` class trigger the same overrides. This lets the gallery test reduced-motion behavior without needing to change OS settings, while real user OS preference still works correctly in production pages.
